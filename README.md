# BinWave

**BinWave** 是 [SoundBin](../) 1.8.5 的开源快照 —— 一个 Electron 写的桌面音效素材管理与试听工具：
把散落在硬盘里的音频索引成可搜索列表，波形试听、修剪、加效果，直接拖进 DAW。

> 想找这个项目？搜 **binwave** 或 **BinWave**（GitHub 仓库名 `ylan58117-svg/binwave`）。

## 直接下载使用（Windows x64）

[**→ 下载 SoundBin 1.8.5 便携包（189 MB）**](https://github.com/ylan58117-svg/binwave/releases/tag/v1.8.5)

解压后双击 `SoundBin.exe`，免安装。两点限制：
- **不含 VST3 运行时**（`pyrt\`，80 MB），所以 VST 插件功能不可用，其余功能正常。
- 只提供 Windows x64 包；macOS 需要自行用 Electron 运行源码。

这是 **SoundBin 1.8.5** 的开源快照，从私有开发线 `SoundBin-Source` 的 `290edc4` 导出。

- 冻结版本：**1.8.5**。开源版不再跟进后续私有版本（1.9 起的派生血缘、质量体检、生成台账等功能只存在于私有线）。
- 用途：学习 Electron 桌面音频工具的实现方式（自定义 `snd://` 协议、Web Audio 波形与效果链、AI 检索三段式、云端音频生成接入）。
- 未包含：作者自己的素材库、密钥、打包产物（`dist/`）、`data/`、`pyrt/`（VST 用的 Python 运行时需自行准备，见下文）。
- 许可：MIT（见仓库内 LICENSE 或 `package.json` 的 license 字段）。

## 跑起来

```
npm install            # 本仓库无三方依赖，这步可跳过
runtime\electron.exe . --user-data-dir=data
```

`runtime\` 不随仓库提供，去 [Electron releases](https://github.com/electron/electron/releases) 下载对应平台的 44.x 解压到 `runtime\` 即可；也可直接 `npx electron .`。

VST3 渲染依赖 `pyrt\`（内置 Python + pedalboard + numpy）与 `src\vst\vst_render.py`，没有 `pyrt\` 时 VST 相关按钮不可用，其余功能正常。

## 目录

- `src/main.js` 主进程：窗口 / 协议 / 素材清单 / 缓存 / 效果器等 IPC
- `src/preload.js` 渲染层可见的白名单
- `src/renderer/` 界面（`app.js` / `index.html` / `style.css`），清单在 `ai.js`（检索）、`fx.js`（效果链）、`sampler.js`
- `src/audio/audio.js` WAV/AIFF 解析、峰值、响度（BS.1770）
- `src/peaks-worker.js` 峰值与深层分析的工作线程
- `build_dist.ps1` 打包脚本（原地保留 `data\`）

## 说明

本仓库不包含任何商业素材、密钥或用户数据；示例素材请自行准备。Issues / PR 欢迎，但作者主要维护私有线，合并会以「不破坏 1.8.5 行为」为前提。


给声音设计用的**素材试听清单**。把散落在硬盘各处的音效拖进来，排成一张表，点一下就能听、能拖、能搜——但文件**一个字节都不会被复制**，它始终待在原来的位置。

它是「听」和「挑」的工具，不是素材管理库，也不是编辑器。挑好之后，直接从列表把行拖进 Pro Tools 的时间线。

## 启动

**平常就用便携版**：双击 `dist\SoundBin\SoundBin.exe`。

它自带运行时，双击即开，数据放在 exe 旁边的 `data\`，整个 `dist\SoundBin` 文件夹拷到 U 盘或另一台 Windows 上照样能用（不需要装任何东西、不需要登录）。生成/更新方式见下面的「打包成 exe」——改了 `src\` 之后要重新跑一次 `build_dist.ps1`，`dist` 里才是新代码。

文件夹长这样：

```
SoundBin\
  dist\SoundBin\          便携版（SoundBin.exe + 运行时 + data\ 你的清单）
  runtime\                开发用的 Electron 运行时
  src\                    程序源码
  build_dist.ps1          把 src 重新打包进 dist\SoundBin
  快捷键.md / README.md / 打包与跨平台说明.md / 压力测试报告.md
```

**改代码时**（开发用），从项目根目录用运行时直接跑源码，用户目录指到临时目录免得污染便携版的清单：

```
runtime\electron.exe . --user-data-dir=%TEMP%\sbdev
```

> 键位和鼠标操作单独整理了一份：[快捷键.md](快捷键.md)（`T`/`R` 缩放、`Ctrl+E` 导出选区、`Ctrl+I` 看元数据、`Ctrl+F` 找相似波形……）。

`src\main.js` 在 `app.isPackaged` 为真时把用户目录指向 exe 旁边的 `data\`，所以便携版的素材清单、资料库、分类都在 `dist\SoundBin\data\library.json` 里，不会留在 `%APPDATA%`——搬走文件夹，清单跟着走。

以前项目根目录还有一份 `data\` 和 `启动 SoundBin.cmd`（开发时用的固定 profile），2026-10-22 已按用户要求删除，旧清单备份在 `backup\library-旧-2026-10-21-45条.json`。

三条约束：

- **文件夹路径里不要有中文**。`electron.exe` 所在路径含非 ASCII 字符时会在启动瞬间崩（0xc0000005），连窗口都不出。放在 `D:\SoundBin`、`E:\Tools\SoundBin` 这类地方都可以。
- 目标机器得是 **64 位 Windows**，运行时就是 `win32-x64` 的。跨到 macOS / Linux 需要另外换运行时。
- 素材本身**不会**跟着走。清单里存的是绝对路径，换台机器后原路径不存在，条目会落到侧栏的「文件缺失」里——重新导入那台的素材即可。

## 设置在哪

标题栏**右上角的齿轮**就是设置入口（`SoundBin` 图标右边不放按钮，省得和窗口拖动区域打架）。

**贴边模式下**，窗口顶上会多一条 `音频 | 设置` 的标签栏——两边随时来回切，不用再去找右上角。这条栏只在你贴着屏幕边时出现，正常窗口下不占地方。

抽屉里从上到下：试听缓存、资料库位置、**贴边隐藏**、**Agent 语义检索**（接口地址 / 模型 / 密钥）、**本机音频插件**、快捷键一览。

## 导入素材

三种方式，都会落到同一张表里：

| 方式 | 说明 |
| --- | --- |
| **导入文件…** | 多选音频文件 |
| **导入文件夹…** | 递归扫描子目录，只挑音频扩展名 |
| 直接拖进窗口 | 文件或文件夹都行，窗口会弹出蓝框提示 |

重复导入会被跳过（按绝对路径去重）。

**大批量导入**：分析是两段式的，第一段只读文件头（几毫秒一个），不读音频内容。实测把 `E:\声音` 整个拖进来，**9271 个文件、107 GB 全部出齐时长/采样率/声道只要 6 秒**（扫描 0.8 秒）。波形和相似度指纹不在这时候算——它们按需算，见下面「试听与波形」。

## 试听与波形

- **单击行** 即播放；再点同一行从头开始。
- **空格** 播放/暂停，**Esc** 停止，**↑ / ↓** 上下换一条。
- 点列表行，底部波形面板显示该文件的完整波形，**红色竖线是播放头**，随声音移动；点波形任意位置即定位到那里。
- 波形左上角那条**窄的时间标尺**里写时间码：波形被裁在标尺下面，振幅再大也压不住时间码（以前大峰值会把刻度盖掉）。
- **波形是按需算的**：第一次看某条音频的波形时要把这段音频完整读一遍（几十 MB 的素材约 0.1～0.2 秒，在独立工作线程里算，界面不会卡），算完存进 `data\cache\peaks`，再看就是毫秒级。导入一万条也不会把所有波形都算出来——内存里只保留最近看过的 8 条。
- 双声道会分上下两条独立波形；单声道合并为一条。
- **波形 适应** 按钮：低电平素材（现场录音常常只有 -30 dBFS）在默认视图下几乎是一条直线。这个开关只放大**绘制**幅度，让你看清包络形状，**不动播放电平**。按钮上会显示当前的放大倍数（如 `×16`）；切到「实际」就是真实振幅。
- 底部 transport 右侧的滑杆调**监听音量**，单位 dB，范围 -60 到 +12；双击滑杆回到 0 dB，按 `M` 静音。它走的是 WebAudio 的 `GainNode`，所以是真的按 dB 增益，不是线性百分比。
- **切换到另一个音频时会自动回到 0 dB**——为上一个文件压低或抬高的电平基本不适用于下一个（一个很响的素材继承 -30 dB 会听起来像坏了）。暂停后继续播同一个文件则保持你调好的值。
- **把行拖出去（拖进 DAW / 资源管理器）时会自动暂停**：拖拽一开始就停声，不会一边找位置一边响；松手后按空格接着听。
- 列表表头的**列宽可以拖动**：把鼠标移到表头某一列的右边缘（光标变成 ⇔），左右拖动改这一列占的宽度；双击该边缘恢复默认。最后一列「路径」没有把手，它吃剩下的空间，别的列变宽它就自动缩。列宽会存进 `library.json`，下次打开还是你调好的样子。

## 波形缩放

波形面板上那些按钮右边的 `×1` 是缩放倍数，后面跟着当前视窗的时间范围。

| 操作 | 效果 |
| --- | --- |
| `T` / `R` | 放大 / 缩小（以指针位置为锚点；指针不在波形上就以播放头或视窗中心为锚点） |
| 滚轮 | 在指针位置缩放（`Shift` + 滚轮是左右平移） |
| 按住中键（或 `Alt` + 左键）拖动 | 平移波形 |
| 双击波形 | 还原到 `×1` 全览（有选区时先清选区） |
| 点 `×1` 倍数按钮 | 同上，回到全览 |

放大到一定程度后，峰值缓存（320 bins/秒）的粒度就不够了，界面会**按需向主进程要当前视窗的原始采样**（`audio:window`，最多 12 MB、按列聚合），继续放大能看到真实的振荡细节，而不是拉伸出来的方块。最大缩放约到「一个像素 1 个 bin」为止。

## 修剪选区与导出（不用开 DAW 就能先切一段）

在波形上用 `Shift` + 左键拖出选区，或者：

| 操作 | 效果 |
| --- | --- |
| `I` | 把选区起点打到播放头位置 |
| `O` | 把选区终点打到播放头位置 |
| `Esc` | 清除选区 |
| `Ctrl+E` / 点「导出选区」按钮 | 把选区写成 WAV，**放在原文件旁边**，命名 `<原名>_trim_<起点>-<终点>.wav`，并自动加入列表 |
| 右键波形 → 导出选区为 WAV | 同上 |

选中范围内的部分会正常显示、外面压暗，播放头和时间也跟着缩放走。
导出是**逐样本裁剪**：16/24/32-bit 整型来源走字节直搬（实测与源文件逐样本相同，误差 0），
float 与位深不同的情况才做一次换算。超过文件末尾的部分会自动截断到末尾。

**标记过修剪区间的素材，播放时只播保留的那一段**：点它开始播会从选区起点起声，播到选区终点自动停（不显示「从头播到尾」再手动拖）。暂停后再按空格也是从选区起点重新开始。想听完整文件就 `Esc` 清掉选区（再按一次 `I`/`O` 重新标记）。

**标记过的素材，直接从列表拖进 DAW 拿到的就是修剪后的音频**，不用先导出、也不用去「经过处理」里翻。拖的瞬间后台已经把它写成裁剪文件（放在 `data\cache\clips\`），拖出去的文件名是 `<原名>_trim_<起点>-<终点>.wav`。列表里这一行的时长显示的是**修剪后**的长度，名字后面带一个橙色「已修剪」小标；`Esc` 清掉选区后拖出去就又是原文件。
注意这是两份东西：**标记区间**只改了「拖出去给什么」和「播放范围」，磁盘上的原文件一个字节都没动；想让新长度落到磁盘上、并作为独立条目出现，请用「导出选区」。
导出出来的新文件会**自动进「经过处理」分类**（见下面「分类」），不用手动归类。

## 音频信息（元数据）

点波形右上角的「信息」按钮或 `Ctrl+I`，右侧滑出面板，显示：

- **文件**：文件名、完整路径、大小、修改时间
- **技术参数**：容器、编码、采样率、位深、声道、时长、采样帧数、峰值电平（dBFS）、是否 BWF、分类
- **BWF BEXT**：描述、制作者、引用、原始时间、bext 版本、UMID、响度（LUFS/LU/真峰值）、编码历史
  （有些库会在这些字段里塞 `\0`、`0x80` 之类不可打印字节，读取时会被过滤掉，不会显示成方块）
- **iXML**：PROJECT / SCENE / TAKE / NOTE / TAPE / CIRCLED 等字段（有就显示）
- **LIST-INFO**：标题（INAM）、艺术家（IART）、备注（ICMT）、日期（ICRD）等
- **ID3 / FLAC / Ogg / MP4**：标题、艺术家、专辑、年份等常见标签
- **封面**：按下面的顺序找，找到一张就停（不会去别的地方乱扫）
  1. 音频里内嵌的图（ID3 APIC / FLAC PICTURE / MP4 covr）
  2. 音频**自己那层目录**里的封面目录：`Artwork` / `Covers` / `Images` / `Pictures` / `Cover` / `Art` …
     —— BOOM、Sound Ideas 这类包习惯把封面单独放一个 `Artwork` 文件夹
  3. 音频**自己那层目录**里的图：先找 `<音频文件名>.jpg` 这种同名图，再找
     `cover* / folder* / front* / album* / artwork* / thumb*`，然后是「目录里的图只有一张」，
     最后才是与目录同名的图
  4. 都没有就**往上找两级**（很多包把封面放在包根，音频在 `包名\子目录\` 里），同样的规则，
     只在包根或它下一层放图也能被认到
  5. 还是没有图 → 列表和详情里显示一张**按目录名生成的占位封面**（稳定的颜色 + 两个字母，
     例如 `MAGIC - Construction Kit` 是 `MC`、`Magic - Designed` 是 `MD`），
     这样即使整包没带图，也能一眼看出素材属于哪个包
- 底部「复制全部信息」一键复制成文本

列表里也多了一列**描述**（来自 BEXT 描述 / iXML NOTE / INFO 备注），以及最左边 34px 的封面缩略图。

## 相似波形搜索

点「相似」按钮或 `Ctrl+F`，右侧列出**与当前音频波形最像**的其他条目，附 0~100 的分数，
点一行即可切过去试听。「相同」标记的是波形几乎完全一致的（分数 100），用来找你重复导入的素材。

原理：每条音频算一个**波形指纹**（64 段归一化包络 + 64 段过零率），
打分时把时长差、包络 L1 距离、过零率相对差加权成 0~100。
指纹要等那条音频的波形算过才有，所以刚导入的库里第一次开「相似」会显示「还有 N 条尚未分析」，
面板开着的时候会一条条补（每秒十几条，结果边算边出现），关掉面板就停；补过的指纹存进 `library.json`，下次打开直接出结果。

## Agent 语义检索（一句话找素材）

不用记素材叫什么，描述你要的声音就行。比如：

> 硬底鞋在狭窄瓷砖走廊里慢走，要有早期反射但不要长混响尾音

点标题栏的星形按钮、波形区的 `AI 检索`，或按 `Ctrl+K` 打开。输入需求后**直接回车就开始检索**（`Shift+回车` 才是换行）：

1. 需求先被拆成**概念标签**——正向的和「避开」的两组分开列出来（「不要 / 避免 / 没有」会被识别成排除项）；
2. 在本地把整个库扫一遍，按名称 / UCS 分类 / 描述 / 目录名加权打分；
3. **配了模型时**：先把需求交给模型拆成检索词（中英文同义词、上位词、材质、动作、速度、空间、距离都列上），
   再拿这些词把**整个库**重新打一遍分——所以不再受「原句里那几个词本地认不认识」的限制；
   初筛最多留 160 条交给模型排序写理由。

**不配模型也能用**，而且这是默认状态。本地那张表有六十来个概念（材质、动作、空间、混响、距离、情绪、生物、机械……），
中英文都认，10 万条扫一遍也就几十毫秒。结果给出百分比和命中理由，「只看结果」可以把列表过滤成这几条。

**看图取声（导入图片）**：Agent 面板里点「＋ 导入图片」，选一张参考图（剧照、参考照片、场景截图都行）。
配了接口时，模型先看这张图，说出「这个画面里会出现什么声音」（分环境层 / 实体层 / 细节层，给 4~8 条具体声音），
再把这些声音翻成检索词，拿回库里做全库匹配，最后照旧由模型复核排序。
需求那一栏可以不填——只给图也能检索；填了就按「图 + 文字」一起理解（例如「只要室内安静的部分，不要鸟叫」）。
- 图片会先缩到最长边 1024 再发（一张 1279×1598 的截图约 118 KB），不会把原图几 MB 直接塞给模型。
- 面板里会显示画面描述和「图里像是有」的几条声音标签，方便确认模型看对了没有。
- 看图失败（接口不支持图片、超时、返回内容为空）会自动重试一次，还是不行就退回纯文字检索，并在图片下方用红字写明原因。
- 只有配了接口才能看图；没配时点这个按钮会直接提示去设置里填。
- **图片不会在搜完之后消失**：搜过一次以后，图片、画面描述、声音标签都留在面板里；这时改文字直接再按「检索」或回车，
  会沿用上一次的画面理解（只重新跑检索，几秒返回），不必重新上传、也不会再让模型看一遍图。
  想让它按新理解重新看图，点「换一张图」换图，或者点「重新看图」强制再看一次。

**「全库扫描」勾选框**：勾上之后，把整库的「名字 + 分类」按 900 条一段发给模型逐段点名（最多看 12000 条，3 段并发），
再和本地初筛合起来排序。这是唯一能让模型「自己翻全库」的路子——本地一个词都没命中也能把素材捞出来，
代价是慢（几分钟量级的库要几十秒）而且费 token，所以默认不勾；没勾时提示条会告诉你「本地+扩词都没命中，可以勾上试试」。

**「保留本地命中」勾选框**（默认勾着）：接了接口之后，模型挑完的那一份结果里，总能混进几条本地概念命中的素材——
勾着的时候，本地命中但模型没挑中的条目会**另附在后面**（行内标「本地命中」，提示条写「模型留下 12 条，另附本地命中 28 条」），
这样模型偶尔看漏、但名字/分类明显对得上的素材不会被悄悄丢掉；关掉它，就只看模型挑出来的那一份。
勾选状态记在 `data\library.json` 的 `settings.ai` 里，下次打开还是你上次的选择。

**安静取向会自动避开「强冲突」的库**：需求里出现「安静 / 宁静 / 安逸 / 舒服 / 清晨 / 阳光 / 微风 / 公园 / 草原 / 森林 /
海边 / 自然 / 户外」这类词时，检索前会先按**库**统计一遍——整库几乎都是爆炸、重击、尖叫、警报、武器、转场提示音的，
整库跳过不参与检索；剩下的库里，自己就是强冲突、又没有任何安静线索的单条也剔掉。
判定只在本地做（名字、UCS 分类、描述、目录名四层线索，不花 token），面板里会用一行小字告诉你
「安静取向：已跳过 1158 条强烈无关素材（爆炸、武器、重击、尖叫），剩下 8113 条参与检索」。
反过来，需求本身就在找爆炸/尖叫/震撼转场时**不做任何过滤**，那些库照常参与。
（实测：9271 条的库，「安逸的公园里，微风拂过草原，远处有鸟叫」→ 跳过 1158 条，前几条落在
`Prairie morning birdsong`、`Country morning birdsong wind`；同一句需求不勾扫描时 12 秒出结果，勾上扫描 42 秒。）

模型只做**重排**，不参与「找」：它只能从候选里挑，所以配错模型也不会把库搜乱。连不上接口时自动回落到本地结果，不会卡住。

**检索结果直接就是可用的素材**：点结果里的任意一条，它立刻被选中并开始在试听，
下面的**波形条、修剪、效果器都还在**（贴边小板子下也一样——面板只占上半截，不会盖住波形和效果器那一行），
所以可以当场试听、切一段、加效果、再拖进 DAW。
列表里的**每一条结果都能直接拖出去**（拖到 DAW、资源管理器都行），拖出去的就是带效果器处理的版本。

**接 Agent（可选）**：设置 → Agent 语义检索，填一个 OpenAI 兼容的接口（DeepSeek / OpenAI / 本地 Ollama 都行）、模型名、API Key。
**填一次就记住**：地址和模型停手 0.7 秒自动存，密钥在失焦或回车时存，不用再点「保存」，下次打开设置已经填好；
密钥本身只回尾号（输入框里显示「已记住（尾号 767a），留空 = 不修改」），明文不出主进程。
存在 `data\agent.json`，能用系统钥匙串（DPAPI）就加密；万一系统加密不可用，会按明文存并在设置里明确告诉你。
「测试连接」会先把界面上刚填的存下来，再发一句「只回复两个字：可用」。
**注意密钥是「绑在这台机器 + 这个 data 目录」的**：Electron 的 safeStorage 会把解密密钥放进 `data\Local State`，
所以把 `SoundBin` 文件夹拷到另一台电脑（或者直接拷 `agent.json` 到另一个 data 目录）之后，密钥解不出来，
设置里会显示成没填。换机器就重新填一次，两秒钟的事。

**用真接口试过**：DeepSeek（`https://api.deepseek.com/v1` + `deepseek-flash`）拆词约 1 秒、终排 5~10 秒，
「电动踏板车在室外缓慢转弯」这类中文需求拆出来的词（`electric scooter / EV / tire / cornering / wet tarmac / exterior`）
能把库里名字带 `Cornering`、`Wet Tarmac` 的素材真的捞出来——原句里的中文词本地根本不认识。
注意新模型会先花 token 写推理过程，`max_tokens` 给小了（比如 16）会出现「HTTP 200 但内容为空」——
所以请求里默认给到 1200~3000，遇到空内容会直接提示你「多半是 max_tokens 被推理吃掉了」。

### 离线开关（连了密钥也能完全不发出去）

Agent 面板里有一个 **「离线（不发送给 AI）」** 勾选框。勾上之后，即使设置里存着接口和密钥，
语义检索也完全走本地：不拆词、不看图、不把候选名字发给模型，界面上连请求都不会发出去。
状态条会写明「离线模式（不发送给 AI）：本地命中 N 条」。
适合素材涉密、或者在算力/流量受限的机器上临时用。
旁边的 **「保留本地命中」** 控制「模型挑完之后，本地初筛的结果还附不附在后面」；两个开关互相独立。

## 效果器（试听时听个大概，也能离线导出）

波形区右上角 `效果` 或 `Ctrl+Shift+E`。挂在试听链上，拖参数立刻听到，不用开 DAW：

- **波形条最左边还有一小块**：一个 `● 效果 ▾` 按钮 + 三个最常用的旋钮（低切 / 高切 / 混响湿声）。关着的时候只占一个按钮的位置，打开才展开旋钮。点按钮（或旁边的 `效果` 片）弹一个菜单：`启用效果器`（旁通）、`内置效果链`、`采样器`、`VST3 插件`、`收起效果器窗口`——选哪个就开哪个，不用再去翻抽屉。**贴边模式下这块只有按钮本身**，点开菜单同样能进任意一个。

- **低切 / 高切**：砍掉低频隆隆声和高频嘶声（默认 20 Hz / 18 kHz）
- **中频**：一个 peaking，中心频率和增减可调（做电话感、贴耳感很快）
- **压缩**：阈值 / 比例，起落时间固定在 8 ms / 220 ms
- **混响**：卷积混响，湿声比例和衰减时长可调（IR 是程序按指数衰减噪声现生成的，不占磁盘）

`Ctrl+Shift+B` 旁通。参数跟着 `library.json` 的 settings 走，下次打开还是这套。

**导出**：面板底部「导出处理后的 WAV」，按当前参数用 `OfflineAudioContext` 离线跑一遍，
24-bit PCM 写盘，采样率跟原文件一致，存到你选的位置，**原文件不动**。导出后底部显示采样率、峰值和路径。

注意：默认拖进 DAW 的是**原始文件**（或修剪后的副本）。但**效果器开着且参数不是直通**时，拖出去的是按当前参数离线渲染好的那一版（下面「拖进 DAW」一节有说明）。

## VST3 插件（用你熟悉的插件过一遍，再拖进 DAW）

效果器面板里点 `效果器 / VST` 进「VST3 插件」抽屉：

1. `扫描` 列出这台机器上的 `.vst3`（同一个目录里的 `.vst3` 外壳也算一条，比如 `WaveShell1-VST3 15.0_x64`）
2. 选中一个插件 → 如果是 1 个参数都没有的，通常就是外壳，点 `列子插件` 把里面的子插件列出来选一个（列不出来时也可以直接把子插件全名填进输入框，例如 `CLA-76 Stereo`）
3. `读参数` 会把这个插件暴露的参数列成滑块；调好以后点 `渲染试听`
4. 渲染完成后，这条素材的**播放/修剪/拖出都改用处理后的版本**（`还原原始` 可以退回原文件），拖进 DAW 拿到的就是处理过的这一版

实现上走的是 `resources\py\python.exe`（内置 Python 3.12 + pedalboard）这个旁路进程，**不是**在 Electron 里加载 native 模块——插件崩了只会让这一次渲染失败，不会把整个界面带走。所以：

- 只支持**效果器**（能接收音频输入的那种）。纯乐器 / 采样器（Kontakt、Serum 之类）不接收音频输入，这里做不了
- 插件的编辑窗口画不出来（没有 UI 宿主），只能用它暴露出来的参数
- 结果缓存在 `data\cache\vst\<参数签名>\` 下，同样的参数再点一次是秒出的
- 有些外壳插件（Waves 最典型）第一次加载要一两分钟，期间窗口不会卡（跑在子进程里），耐心等状态栏出结果就行
- 渲染超时是 240 秒，超时会杀掉子进程并报错，不会留下半截文件

## 采样器（先把它玩成新素材，再拖进 DAW）

效果器菜单里选 `采样器：变调 / 循环 / 包络…`，打开右侧「采样器」抽屉。**采样源永远是当前选中的那条音频的原始文件**，不会层层叠加已处理的结果：

- **起点 / 终点**：只取这一段做采样源（拖到"终点"最右端就是整段）
- **循环**：开 / 关。开着时按住键会一直循环，松开后走释放
- **音高 / 微调**：±12 半音 / ±100 音分，按比例改变播放速度，所以变高会短、变低会长（采样器的老规矩，不是 time-stretch）
- **启动 / 衰减 / 延音 / 释放**：标准的 ADSR 包络
- **低通 / 高通**：一阶滤波器，用来削掉刺耳的高频或发闷的低频
- **音量 / 声像**：-24 ~ +12 dB，声像 -100% ~ +100%
- **键盘试听**：13 个键（鼠标按住可用），或者直接用 `A W S E D F T G Y H U J K` 这排字母键弹——W/E/T/Y/U 是黑键
- **试听** 按钮会按"1 号键"（原调）播一次，按钮会变成 `停止`；`渲染成这个版本` 用 `OfflineAudioContext` 离线渲染成 24-bit WAV

渲染完以后，这条素材的**播放、波形、修剪、拖出、效果器、VST 都用这一版**（拖进 DAW 拿到的也是它），`还原原始` 退回原文件。缓存放在 `data\cache\sampler\<参数签名>\<原名> (sampler).wav`，同样的参数再点一次是秒出的。

和 VST3 那套的区别：采样器是程序自己实现的（变调 / 包络 / 滤波 / 声像），不需要插件、不依赖 Python，渲染一次几毫秒；但它不是 VSTi——不接受 MIDI 输入，也不会把插件界面画出来。

## 贴边隐藏（QQ 式自动收起）

设置 → 贴边隐藏：选贴左边还是右边、宽度（320 ~ 半屏，默认 480），打开开关，窗口就贴在那条边上铺满可用高度。

- 鼠标离开窗口约半秒，窗口收起成屏幕边缘的一条细条（Windows 会把窗口宽度夹到三十几像素，8 px 的细条做不出来）
- 鼠标移到那条边上，面板滑出来；再移开又缩回去
- `Ctrl+Alt+S` 是键盘开关：按一下固定展开，再按一下收起。**键盘展开的不会因为鼠标移开而缩回去**，方便一边听一边调。这个快捷键在开关关着的时候也有效——按下会直接把设置打开并提示你去哪一栏打勾
- 窗口顶上多一条 `音频 | 设置` 标签栏：贴着屏幕边时随时在素材页和设置页之间切，不会再被卡在设置页里出不来。从设置里把开关打开后也会自动切回音频页
- **面板内侧那条边可以直接拖**：贴着右边的就往左拖变宽、往右拖变窄（贴左边的反过来），松手后宽度记进设置。不用每次都跑回设置页拉滑块
- **拖标签栏等于拖窗口**：按住顶上那条 `音频 | 设置` 往屏幕中间拽，窗口会从边上跟出来，**贴边隐藏顺带就关掉了**，落点就是你松手的位置。想恢复原样就再回设置里打开一次
- 宽度不会超过半个屏幕。窗口只有四五百像素宽时会自动切成紧凑布局：**左边资料库和分类还在**（只是压窄），列表只留序号 / 名称 / 时长，波形区的按钮换行
- **音量在底部那排的右边**：时间码右边的空白里有一个小旋钮（圆盘 + dB 读数），和 transport 那条长滑杆是同一个值。按住它往上/往下拖就是调音量，**默认每像素 0.5 dB（粗调），按住 `Alt` 再拖变成每像素 0.1 dB（精调）**，滚轮也能转，双击回 0 dB。贴边时那条长滑杆会收起来，只留这个旋钮，免得挡住波形
- 万一哪次收起/展开之后面板整块变黑（Windows 偶尔会丢掉窗口表面），不用重开：程序自己会重绘，8 秒还没恢复就把窗口隐藏再显示一次，把表面重建回来，过程记在 `data\ui.log`

关掉开关，窗口还原到原来的位置和大小。

## 本机插件清点（只看，不加载）

设置 → 本机音频插件 → 扫描，会去这几个地方找 `.vst3` / `.dll` / `.clap`：
`C:\Program Files\Common Files\VST3`、`%APPDATA%\VST3`、`C:\Program Files\VstPlugins`、
`C:\Program Files\Steinberg\VSTPlugins`、`C:\Program Files\Common Files\CLAP`、`%APPDATA%\CLAP`。

扫描结果现在有两个去处：设置页里那份清单（只是告诉你「这台机器上有什么」），以及效果器抽屉里的「VST3 插件」面板（那才是真正用来跑插件的入口，见上一节）。

**为什么不在 Electron 里直接加载插件**：那要 native 模块，插件一崩会把整个界面带走，而且编辑器窗口也画不出来。现在的做法是把插件放进 `resources\py\python.exe` 这个旁路进程里跑，只拿它渲染出来的音频回来。

## 拖进 DAW

> 拖出前会先弹一句「正在准备拖出的文件…」：如果开了效果器或划了选区，程序要先把这一段渲染成 24-bit WAV，几秒的等待是正常的。原生拖拽在 Windows 上是主进程里的模态循环，个别 DAW 接收后不还焦点，所以拖完会主动把窗口拉回前台并重绘一次；万一把拖拽吃掉了，90 秒后也会自动复位，不会一直卡在「正在拖」的状态。

**按住列表里的一行，直接拖到 Pro Tools 的时间线 / 素材窗 / Finder 里**。拖出去的是原始文件（Windows 原生文件拖拽，CF_HDROP），DAW 拿到的是它自己的路径，和你在资源管理器里拖过去完全一样。拖动过程中那一行会变暗（`opacity: .45`）表示「正在拖的是这条」，松手就恢复原样——拖起又原地放下也一样。

**打了修剪区间的素材例外**：拖出去的是按区间裁好的 WAV（后台在 `data\cache\clips\` 里生成，与源区间逐字节相同），文件名带 `_trim_<起点>-<终点>`。所以「剪掉前半段、只往 DAW 里放后半段」现在的做法是：在波形上拖出要保留的那段 → 直接从列表拖进 DAW，中间不用导出。想还原成整条就把选区 `Esc` 清掉。

**效果器开着的时候，拖出去的是处理过的那一版**：渲染层用当前效果器参数离线跑一遍（24-bit PCM，采样率跟原文件一致），存到 `data\cache\fx\<参数签名>\`，文件名带 ` (fx)`，拖出去的就是这个文件。参数一改签名就变，会重新渲染一份；参数是直通（低切 20 Hz / 高切 18 kHz / 中频 0 dB / 混响干 / 压缩关）或者开关关着时，还是给原始文件。修剪区间 + 效果器两个都开着时，先渲效果再按区间裁剪，文件名是 `名字 (fx)_trim_起点-终点`。

渲染要花时间（几十秒的素材一般不到一秒），拖出去的动作会等它一下，所以第一次拖会稍微顿一下，之后再拖同一个文件直接用缓存。

可以多选后一起拖；多选里带修剪标记的会各自给自己的裁剪文件，没标记的给原文件。

## 资料库（自己建的分组）

左侧栏「资料库」下面可以建任意多个自己的库，用来把素材归堆。

| 操作 | 怎么做 |
| --- | --- |
| 新建 | 右键「资料库」标题（或右键侧栏空白处），或点标题右侧的 `＋`，输入名字回车 |
| 改名 | 右键那个库 → 重命名… |
| 删除 | 右键那个库 → **删除资料库…**，一步删掉，底部会留 12 秒「撤销」。**只属于这个库的音频会一起从列表移除**（磁盘文件不动）；同时还在别的库里的，只摘掉这个库的标签 |
| 放进库 | 选中若干行 → 右键 → **加入资料库…** → 选一个库 |
| 放进库（拖） | 直接把文件夹或文件**拖到侧栏那个库上**，松手后导入并归入该库；库上会有高亮提示 |
| 边拖边建库 | 把**一个或多个文件夹**拖到「资料库」标题或它下面的空白处 → 每个文件夹各建一个同名的库，里面的音频全部放进去（同名库已存在时改为加进那个库，不会建重复的） |
| 加到当前库 | 先点选一个库（列表只剩它的成员），再把文件夹拖到**右侧列表区** → 全部加入这个库 |
| 移出 | 进到那个库的视图里 → 右键行 → **从「库名」移出** |
| 看某个库 | 点侧栏那个库，列表只剩它的成员，其他筛选照常叠加 |
| 多选 | 按住 `Ctrl` 点多个库（再点一次取消），或按住 `Shift` 点一段范围；`Esc` 全部取消。选中时列表显示它们的**合集** |
| 合并 | 多选后**右键任意一个被选中的库** → **合并所选 N 个资料库**，合成一个「合并资料库」（已有同名就依次叫「合并资料库1」「合并资料库2」…） |
| 批量删除 | 多选后右键 → **删除所选 N 个资料库**，同样留 12 秒「撤销」（只属于这些库的一起移除，多归属的只摘标签） |

一个音频可以同时属于多个库。库名后面的数字是成员数。整个清单只有一份，库只是给条目打的标签——所以「全部音频」永远是全集。

删除做成「一步 + 撤销」而不是「两步确认」，是因为确认框会弹在原菜单的同一个位置、同样的宽度，看起来像点了没反应。库本来就只是标签，删错了撤销就行。

文件名不符合 UCS 规范的素材会进侧栏的**未分类**桶——那是个正常的分类，点它就能筛出这些文件，按上面的办法归进自己的库即可。

## 分类

侧栏「分类」里的条目，初始来自文件名的 UCS 前缀（`Category_SubCategory_Description_Number` 的第一段），但它们从此是**可编辑的数据**，不再是只读的推导结果：

最上面那条 **「经过处理」是内置分类**：用「导出选区」（`Ctrl+E`）剪出来的音频会自动落进这里，方便你把加工过的版本和原始素材分开。它固定排在第一位、不能改名也不能删除（右键里会显示「内置分类，不能删除」），把里面的素材移到别的分类或者从列表移除都没问题。没有任何处理后素材时它显示 0，不会自动消失。

| 操作 | 怎么做 |
| --- | --- |
| 新建 | 右键「分类」标题（或右键侧栏空白处），或点标题右侧的 `＋`，输入名字回车 |
| **新建子分类** | 右键某个分类 → **新建子分类…**；也可以在「移动到分类…」的对话框里就地新建，新分类会自动挂到当前分类下面 |
| 展开 / 收起 | 有子分类的文件夹左边有个**倒三角**，点它展开或收起（不会触发筛选）；有没有子分类都占同样的位置，层级用缩进表示 |
| 改名 | 右键那个分类 → 重命名… |
| 删除 | 右键那个分类 → **删除分类…**，一步删掉 + **12 秒撤销**；这个分类**连同里面的子分类**下的音频会**一起从列表移除**（磁盘文件不动），不会退到「未分类」 |
| 移动 | 选中若干行 → 右键 → **移动到分类…** → 选一个分类（也可以就地新建一个） |
| 移动（拖） | 把文件夹或文件**拖到侧栏那个分类上**，松手即导入并归入 |
| 边拖边建分类 | 把**一个或多个文件夹**拖到「分类」标题或它下面的空白处 → 每个文件夹各建一个同名的分类，里面的音频全部归入 |
| **拖文件夹建子树** | 拖进去的文件夹里**还有子文件夹**时，会照着目录结构建一整棵树：主文件夹是分类文件夹，里面的每个子文件夹各是一个子分类，音频跟着自己所在的目录走（多层目录也照样套下去）。只给确实含音频的分支建分类，空目录不会冒出来 |
| 归入当前分类 | 先点选一个分类，再把文件夹拖到**右侧列表区** → 全部归入这个分类 |
| 多选 | 按住 `Ctrl` 点多个分类，或按住 `Shift` 点一段范围；`Esc` 取消。选中时列表显示归入这些分类的全部音频 |
| 合并 | 多选后右键 → **合并所选 N 个分类**，合成一个「合并分类」（重名依次叫「合并分类1」「合并分类2」…） |
| 批量删除 | 多选后右键 → **删除所选 N 个分类**，里面的音频一起从列表移除，留 12 秒撤销 |

多选只对**真实存在的**库/分类生效——「未分类」是个桶，不是一条记录，所以它不参与多选。

**分类可以套文件夹**：右键任意分类选「新建子分类…」，它就成了一个能展开的文件夹（左边有倒三角，点一下展开/收起）。
层级不限于两层，想套多深都行；列表里用缩进表示层级，文件夹右边显示的是**整棵子树的条数**。
点一个文件夹就是「看这一整棵子树」的音频；把音频拖到文件夹上，它就属于那个文件夹本身，不会被自动塞进某个子分类。
删除文件夹会把整棵子树一起删掉（同样 12 秒撤销、磁盘文件不动）。

**整包拖进来就是一棵树**：把素材包的主文件夹直接拖到「分类」区块上，主文件夹变成分类文件夹，里面的子文件夹各变成子分类，音频按目录归位——
实测的落点是：`影视素材\` 根目录下有 1 条音频、下面 `恐怖\`（1 条 + 它自己的 `敲门\` 1 条）、`日常\`（1 条），拖一次就得到
`影视素材(4)` → `恐怖(2)` → `敲门(1)`、`日常(1)`，条数都是整棵子树的。
子分类会跟着目录里的图片走：**每一层的封面只影响它自己那一层**——根目录的 `cover.png` 只给根目录的音频，
`恐怖\cover.png` 给 `恐怖\` 的音频，`敲门\` 自己没有图就往上找一层拿到 `恐怖\` 的封面（`日常\folder.png` 同理）。
所以「大文件夹和子文件夹里的图片」都不会白放，列表最左边那 34px 的缩略图会跟着分类层级各自显示。

一个音频**只属于一个**分类——这跟资料库不同，资料库是可以挂很多个的标签。名字不符合 UCS 规范的素材会落在「未分类」里，点开它、再移动到你自己建的分类即可。

**删除分类会把里面的音频一起从列表移除**（撤销窗口 12 秒）。这是刻意的：删掉一个分类通常意味着「这批东西我不要了」，让它们散进「未分类」反而更难收拾。磁盘上的音频文件一个字节都不会动，撤销或者重新导入就回来了。

拖拽的落点决定结果：落在某个库/分类的**行**上是"加进去"，落在**区块标题或空白处**是"照文件夹名新建一个"（一次拖多个文件夹就是各建一个；拖到「分类」区块上时还会按目录结构建子树），落在**列表区**是"加到现在选中的那个（如果选了）"。夹在文件夹里的散文件会在同一次操作中普通导入，不会因为凑不出名字就被丢掉。

删掉一个 UCS 分类后，以后导入同前缀的文件不会把它复活：那个前缀会被记住，文件直接进「未分类」。（只对**自动生成的**分类记前缀；你自己命名的分类删了就是删了，不会影响以后导入时的自动归类。）

## 搜索与筛选

- 搜索框：匹配文件名、UCS 分类、完整路径。命中的文字会被高亮。按 `/` 聚焦。
- 左侧栏按分类过滤（分类怎么来的、怎么改，见上一节），并统计格式分布、总文件数、总大小、**已知总时长**。
- 点表头可按名称 / 时长 / 格式 / 采样率 / 位深 / 声道 / 大小 / 路径排序，再点一次反向。
- 右键菜单：试听·暂停、在资源管理器中显示、复制文件路径、复制文件名、加入资料库…、移动到分类…、从列表移除、用系统播放器打开。
- `Delete` 从列表移除（**只移除记录，不删文件**），`Ctrl+Z` 撤销。
- 「文件缺失」一项会列出被移走或改名的条目，方便你发现断链。
- 点一条音频，**右侧会展开信息栏**（文件名、路径、大小、修改时间、技术参数、分类、封面、内嵌标签）。它占的是工作区的第三列，不是浮层，所以列表和波形都不会被挡住；关掉之后按 `Ctrl+I` 或点波形区的「信息」还能再打开，也可以让它永久停用（关一次就不再自动弹）。
- 信息栏只在普通窗口里自动出现；贴边面板太窄，点音频不会盖住列表，需要时点「信息」。
- 左侧栏右边缘有一条**拖拽条**，按住左右拖动可以调宽度（150~360，贴边面板里 100~240），宽度会被记住。
- 列宽也记住了：进出贴边面板时列数会变（11 列 / 4 列），程序会自动回落到对应的默认列宽，不会把「名称」挤成几个像素。

## 支持的格式

| 格式 | 波形 | 试听 |
| --- | --- | --- |
| WAV / BWF / RF64 / W64（8 / 16 / 24 / 32-bit PCM、32/64-bit float、A-law、μ-law） | 自解析 | 直接播 |
| AIFF / AIFC（含 80-bit extended 采样率） | 自解析 | 自动转一份临时 WAV 到缓存再播 |
| MP3 / FLAC / OGG / Opus / M4A / AAC | 浏览器解码 | 直接播 |
| SD2 / CAF / AMB / WV / APE / AU / WMA | — | 仅作为条目列出，不可试听 |

WAV / AIFF 的解析是手写的（不依赖 ffmpeg），所以**不支持的编码会明确标出来**，不会假装能播。

标签（BEXT / iXML / LIST-INFO / ID3 / FLAC / Ogg / MP4）也是手写解析的，只读不写——
SoundBin 不会修改你的素材文件。

## 文件在哪

**素材本身**：原地不动，程序只记住路径。

**程序自己的数据**：`data\`（启动脚本用 `--user-data-dir` 指过去的，所以跟着文件夹走）

```
data\library.json          你的清单（路径、大小、时长、格式、所属资料库与分类、波形指纹）
data\cache\peaks\*.bin     波形峰值缓存，每个文件一个（键 = 路径 + 大小 + 修改时间）
data\cache\wav\*.wav       AIFF 转码的临时试听副本
data\cache\art\*           封面图缓存（从音轨内嵌图或同目录封面图抽出来的）
data\cache\clips\*.wav     拖出去用的裁剪副本（只给打了修剪区间的素材生成）
data\cache\fx\<签名>\*.wav  拖出去用的效果器渲染副本（参数一变就是另一个签名目录，清缓存会一起清掉）
data\cache\vst\<签名>\*.wav VST3 插件渲染结果（插件 + 参数 + 素材一起算签名，命中就是秒出）
data\agent.json            Agent 接口地址 / 模型名 / 密钥（密钥能加密就加密，绝不进 library.json）
data\ 其余                 Electron 自己的 profile（缓存、Local Storage 等）
```

设置面板里能看到缓存占用并一键清空。删了缓存只会让波形重新算一遍，不影响素材。整个 `data\` 删掉就是重置出厂状态。

## 压力测试

最大能放多少条、导入多快、内存吃多少，都实测过，数字在 [压力测试报告.md](压力测试报告.md)：
**10 万条（102,000 个文件，938 MB）在这台机器上导入约 12.5 秒、清单载入 0.8 秒、渲染进程 JS 堆约 125 MB，
滚动和搜索仍然跟手**（搜索 10 万条 ~2 ms，滚动 p50 4.8 ms/帧）。瓶颈是主进程的标签解析 IO 和保存清单那一下，不是列表渲染。

真实素材库里的一次实测（当前这套两段式分析）：`E:\声音` 整个拖进来，**9271 个文件 / 107 GB**，扫描 0.8 秒、
元数据出齐 6.0 秒，导入全程界面可操作；此前那套「导入时就给每条算波形峰值」的做法，单个文件要 70~190 毫秒，
同样是这批素材要几分钟并且把主进程内存吃到几个 GB。

分类特别多的情况也修过：同一份清单里有 **1553 个分类**，早期侧栏每画一行都要扫一遍素材（还要 `find` 父级），
一渲染 2.6 秒、点一下卡 5 秒；现在一次遍历把每棵子树的计数算好，1553 行全展开 3~18 毫秒，点分类不再卡。

### 几个刻意的选择

- **为什么必须是 Electron**：只有 `webContents.startDrag` 能产出 Windows 原生文件拖拽句柄，把真实路径交给 Pro Tools。浏览器里 `DataTransfer` 拖不出文件。
- **为什么 UI 和音频走同一个 `snd://` 协议**：跨源加载的 `<audio>` 接进 `MediaElementAudioSourceNode` 会被 CORS 静音——表现就是「音量滑杆看着在动但没声音」。同源就没这个问题。
- **为什么用 `<audio>` 而不是 `AudioBufferSourceNode`**：一个 5 分钟的 96k 立体声素材解码成 float 要 200 MB 以上。`<audio>` 是流式的，内存恒定；波形另算。
- **波形峰值独立缓存**：`320 bins/秒`，每个 bin 存 `Int16` 的 min/max，双声道交错。滚动列表时不会反复读几 GB 的素材。

## 踩过的坑
- 业务抽屉都用 `.settings`(z-index 101)，后出现的会盖住先出现的：设置抽屉必须显式提到 `#settings { z-index: 131 }` / `#settingsScrim { z-index: 130 }`，否则从 AI 工具点「管理…」打开设置会被 AI 面板压住（看着像没反应）。
- 生成类接口的质量问题要拿数据说话：同一句 prompt 生成的「安静街道」实测 RMS −18 dBFS、100% 的 0.5 秒块都高于 −30 dBFS、块间起伏仅 2.3 dB，而库里同类真实素材是 −27 dBFS / 5.6 dB 起伏 / 97% 能量 <200 Hz —— 说明模型给的是连续厚噪声，不是稀疏事件，这类需求别指望生成。

- 「AI 音效库」有两套入口，别只改一处：侧栏「资料库」那一行走的是 `computeView()` 里的 `f.type === 'ai'` 分支（按 `categoryDescendantIds(AI_ROOT_ID)` 过滤），分类树里另有一个真实根分类 `cat_ai_lib`（生成批次是它的子分类）。只改树不改进滤器，或者反过来，都会出现「点进去空/分类里有但看不到」。
- 想伪造「文件缺失」做测试，不能改文件名再重扫——重扫会把新名字当成新条目、`missing` 仍是 false；直接改内存里的 `it.missing = true` 再 `renderAiResults()`。
- 打包 zip 用 Python 的 `zipfile` 更稳：PowerShell 里 `[System.IO.Compression.ZipFile]::Open/OpenRead` 在这台机器上偶发返回 null（报「不能对 Null 值表达式调用方法」），逐文件 `CreateEntry` 全部失败。

- **`agent:chat` 返回字段是 `text`，不是 `content`**：翻译/重排都读 `r.text`，读 `content` 会拿到空串、表现是「翻译没生效、原样发出去」而且不报错。
- **`deepseek-flash` 先花 token 思考**：同一句翻译给 220 tokens 会「思考吃光预算、正文为空」直接 `ok:false`，给到 900 并重试一次才稳；提示词里也要写「只输出英文、8–25 词」压住啰嗦。
- **Stability 内容审核会 403**：`content_moderation` + `flagged`，**不计费**；翻译提示词里要避开 slam/smash/explode/scream 这类词，否则一句正常的「关门声」也会被拦。

- **余额要按秒折算**：Stable Audio 实测 12 秒 44.1k 立体声约 18.8 credits（≈1.57 credits/秒，1 credit = $0.01），所以「还能生成多久」= `credits / 1.57`；只有 Stability 有 `/v1/user/balance`，ElevenLabs 与自定义服务只能显示「余额 —」。

- **别给多选再套一层「暂存区」**：列表本来就支持 Shift 区间选 / Ctrl 加选，拖拽由 `dragPathsFor(item)` 判断——`state.selection.size > 1` 时把整个选择集交给系统，一次拖出多条。1.8.0 曾另建 `state.bin` + 抽屉，结果多了一套要同步的状态（删条目、缺文件、持久化），1.8.1 全部删掉。
- **按钮绑定要跟着 markup 一起搬**：把「生成」块从设置页搬到 AI 面板时，只改了 HTML，`btnGenRun` 的 listener 还留在被删掉的那段里，表现是点「生成」毫无反应、控制台也不报错。整块 UI 换位置后，先 grep 一遍 `$('id')` 绑定是否还在 init 里。
- **生成密钥跟 profile 绑死**：`safeStorage` 加密的密钥和该 user-data-dir 的 `Local State` 是一对，把 `gen-profiles.json` 从打包版拷到另一个 profile，`hasKey` 仍是 true 但解密出来是空串，报「这套配置还没有密钥」。换 profile/换机器必须重新填一次 key。


- **调层比例时不能重新归一化**：造声的「详细」面板拖滑杆如果每次都按 `targetLufs` 归一，整体会被重新压到 −23 LUFS，拉低一层立刻被抬回来，听感上「拉到底还在响」（用户原话）。做法是拖比例时传 `targetLufs: null`，再用生成时记下的 `masterGainDb` 整体缩放。
- **去掉归一就得自己管峰值**：不归一时多层叠加很容易过载（实测峰值 +1.06 dBFS 已削波）。缩放后要测一次峰值，超过 −0.3 dBFS 就整体再压回去。
- **叠加导出要按 `% buffer.length` 平铺**：只播一遍会在结尾留静音、循环时有接缝；平铺 + `tanh` 软限幅再编码。
- **往叠加里加素材要按「文件还在不在」筛**：相似波形 / AI 检索结果里混着丢失素材（清单里 `missing: true`），直接取前 10 条往往 9 条解码失败，看起来像按钮坏了。做法是先 `list.filter(m => !m.it.missing)` 再截 10 条，并把失败条数与原因（文件缺失 / 解码失败）写进状态行。
- **解码是瓶颈，不是入库**：加进叠加要整条 `decodeAudioData`（96k/24-bit 的几分钟素材要好几秒），所以批量加入要逐条报进度「正在加入 3/10」，不要让界面静默卡住。



这些都是真出过问题、排查过、改好的地方。动相关代码之前先看一眼，能省掉重来一遍的时间。

### 环境

- **`electron.exe` 自身的路径不能含中文**。放在 `D:\工作区\...` 下会**启动即崩**，没有任何输出，事件日志里只有 `Application Error 1000` / 异常代码 `0xc0000005`（访问冲突），偏移 `0x7d3267b`。注意：只有**二进制所在路径**有关，源码路径含中文没事（实测过）。所以整个工具放在 `C:\Users\37450\Desktop\SoundBin` 这种纯 ASCII 路径下。
- **`ELECTRON_RUN_AS_NODE=1`** 若在环境变量里，`electron.exe` 会变成纯 Node 进程，报 `Cannot find module 'electron'`。启动脚本里有 `set "ELECTRON_RUN_AS_NODE="` 就是为了清掉它。
- **`startDrag` 会阻塞到用户松手**，所以自动化测试没法完整验证「拖进 Pro Tools」这条链路，只能手动试。

- **响度别写死系数**：BS.1770 的 K 加权两级（high-shelf 1681.97 Hz / highpass 38.14 Hz）要按采样率用 RBJ 公式现算，44.1/48/96k 各算一次；写死 48k 的系数测 96k 素材会偏 1–2 LU。
- **WAV 的 LIST-INFO 只能装 Latin-1**：写回标签时含中文的字段要跳过并告诉用户，不要硬塞（写进去是乱码，其他软件读出来也是乱的）。中文标签靠文件名（UCS）表达。
- **`ZipFile.CreateFromDirectory` 的根目录是入参目录的"叶子名"**：要得到 `SoundBin\...` 就必须把 `...\dist\SoundBin` 本身传进去；传暂存父目录会变成 `pack\SoundBin\...`。
- **改素材路径要一次性搬全**：`relinkItemPath` 不只要改 `path`，还要清 `peaks/peaksState/fp`、搬 `state.byPath`、改 `selection/focusPath/currentPath`、删 `deepCache` 与该路径前缀的 `fxDragCache` 键，否则旧条目会拿着旧波形/旧指纹继续显示。
### 代码

- **造声候选要复用主播放器，别另开一个 `<audio>`**：候选行点一下应该走 `selectItem(it,{play:true})`，所以给候选造一条「临时条目」（`preview:true`、`analysis:'ready'`、`meta.duration` 取 stats.seconds、`peaks:null`、塞进 `state.byPath`）。这样波形、选区、修剪、拖出 DAW 全都是现成的；另开 `<audio>` 会出现「按空格在放列表里的歌、候选自己还在响」的串音。
- **改了候选的音频文件，要记得把「临时条目」指过去**：`retargetSynthItem(it,c)` 更新 `path/playPath/meta.duration`、清 `peaks`，再同步 `state.byPath / currentPath / selection / focusPath`，否则播放器还停在旧文件、波形也对不上。
- **拖完比例不要点按钮**：滑杆 `input` 后 220 ms 防抖调 `applySynthDetailLive(idx)`；用 `synth.liveBusy` 锁 + `synth.liveAgain` 排队，避免连拖时几路重合成打架。缝合类要重新解码素材（60 秒约 15–20 秒），纹理类 0.3 秒内出结果。

- **把抽屉并进面板时，`synth.open` 要跟着板块走**：造声原来是独立抽屉（`#synthPanel`），并进 `#aiPanel` 后「开着」不再是 DOM 的 hidden，而是「AI 面板开着 + 当前板块是 synth」。`setAiTab()` 里同步 `synth.open`、切板块时 `synthStop()`，`closeAiPanel()` 里也要把它收掉；否则试听会继续放、Esc 判断也会错。
- **模型下拉要跟着「当前生效的那套」刷新**：`renderAiModelBar()` 早先写成「优先保留当前选中值」，换配置后另一个板块的下拉就停在旧值上；正确做法是每次都按 `state.agentProfiles.active` 重置 `select.value`。

- **推理模型会把 max_tokens 烧在思考上**：`deepseek-flash` 这类模型对 80 条候选取层，`maxTokens: 1400` 会直接返回空 content → `ok:false` → 静默走本地降级，界面上只看到「本地降级」四个字。造声三处 `agent:chat` 的预算现在是 expand 3500 / 分层 3500 / 纹理 1500，失败原因要写进 `synth.degradeReason` 并显示在状态行。
- **日志时间是 UTC**：`ui.log`、`save.log` 用 `new Date().toISOString()`，比本地慢 8 小时；对录屏/崩溃时间线前先换算，否则会以为应用「提前」挂了。
- **造声的入口和名字**：功能叫「造声 · 合成环境底噪」（原来叫「生成底噪」藏在效果菜单里）。改动它时要同步三处：AI 面板按钮行 `#btnSynthOpen`、效果菜单项、`openSynthPanel()` 里的 `renderSynthCandidates()`。
- **`clampXxx()` 会静默丢掉它不认识的字段**。`clampSynth()` 只返回 seconds/layers/xfade/targetLufs，
  所以把 `mode`/`color` 拼进 `clampSynth({...})` 再取返回值，模式永远是默认值——表现是界面选了
  「纹理合成」却走了缝合。凡是"夹紧函数 + 额外开关"的组合，夹完要再把开关挂回去。
- **循环接缝不能用"斜率相减"来判断是否无缝**。`seamError()` 是早期指标：它把接缝跳变减去两侧
  斜率均值，遇到真实素材的宽带噪声时这个估计本身就不准——实测 60 秒海浪底噪 `seamError` 0.027
  （看着像有台阶），可接缝跳变只有 0.0009，而相邻样点的中位数是 0.0032，接缝比正常波形起伏还小。
  现在的判据是 `seamRatio()`：接缝跳变 ÷ 素材 99.9% 分位的相邻样点差，< 1 就算无缝。
  `seamError` 留着只做测试对照，`stats.seamOk` 已经改用 `seamRatio`。
- **生成出来的文件不能再当原料**。底噪写进 `<数据目录>\generated\` 之后也进了清单，
  如果不排除，用户第二次生成就会拿上一次的成品当素材，越叠越糊。`synthPlan()` 里
  用 `/[\\/]generated[\\/]/` 过滤掉这些路径。
- **悬停试听的定时器一定要能被取消**。`queueHoverPreview()` 里有两个定时器（700 ms 起播、8 秒自动停），
  它们必须在 `mouseleave`、`mousedown`、`dragstart`、列表滚动、行被删、切换资料库这些时候全部清掉；
  漏一个，鼠标已经走了音频还在响，用户会以为程序卡了。判断"要不要抢"的条件是
  `state.playing && currentPath !== it.path`——有人在听别的条目时就别打断。
- **数据位置的指针不能放在 data\ 里**。要搬走的正是 `data\`，指针写在自己家里等于把梯子架在自己脚下；
  所以 `data-location.json` 放 `%APPDATA%\SoundBin\`。另外 `--user-data-dir` 命令行参数必须优先于它，
  否则开发时用临时 profile 会被用户上次的选择劫持。
- **备份文件名要能区分"自动"和"手动"**。自动那份是 `library-YYYY-MM-DD.json`（每天一份、保留 7 天），
  手动备份若也用这个格式，就会把当天自动那份覆盖掉——手动那份必须带 `-HHMMSS`，
  恢复时两种都要认（正则统一成 `BACKUP_RE`）。
- **迁移数据目录之后要重启才生效**。`storage:migrate` 只负责复制 + 写指针，当前进程的 `userData`
  不会当场改变；UI 上直接 `app:relaunch()`，别让用户以为"没生效"又点一次。
- **删数据之后必须自己重画侧栏**。`deleteCategory()`（单个删除）以前只做 `computeView(); scheduleRender(); scheduleSave();`，
  而 `scheduleRender()` 只跑 `renderList()`，不碰侧栏——于是数据删了、侧栏那一行连计数还留在屏幕上，
  看起来就是"删了但分类还在，点进去又是空的"。批量删 `deleteCategories()` 结尾本来就有 `renderSidebar()`，
  所以只有右键单个删除会犯这个错。凡是在渲染层直接改 `state.categories` / `state.items` 的地方，
  都要顺手问一句「哪个 DOM 会因此变旧」。
- **`updateWavePanel` 和 `ensurePeaks` 会互相递归**。`ensurePeaks()` 在 `peaksInflight.set()` **之前**就调了
  `refreshWaveIfCurrent()`，而 `refreshWaveIfCurrent()` 又回到 `updateWavePanel()`、后者再次 `ensurePeaks()`——
  第二次进入时 inflight 里还没有这条，于是无限递归，最后 `RangeError: Maximum call stack size exceeded`。
  表现不是报错弹窗，而是「导入图片没反应 / 点哪儿都卡着」：渲染进程的调用栈被这一个循环占死了。
  修法三条一起上：`peaksState = 'loading'` 提前设、`refreshWaveIfCurrent` 挪到 inflight 写入之后、
  `updateWavePanel` 加 `wavePanelBusy` 防重入 + 调用前检查 `peaksState !== 'loading' && !peaksInflight.has(path)`。
  判断这类问题**别只看截图**：CDP 截图能拍到画面，但窗口真实像素是黑的、DOM 里的调用栈已经爆了。
- **贴边面板的「收起」不能只信主进程发来的 `hidden`**。`dock:mode` 是异步消息，拖宽或动画被打断时，
  渲染层可能先收到「已收起」，于是给 `body` 加上 `dock-collapsed`、把标题栏/列表/波形全部 `visibility:hidden`，
  而窗口实际还停在半屏宽——用户看到的就是一整块黑屏（只剩右边缘那条蓝色 `edge-strip`）。
  现在渲染层按**真实窗口宽度**判断（`hidden && innerWidth <= 80` 才算真收起），再加一个 `resize` 兜底自愈；
  主进程在动画结束后 60 ms 再补发一次权威状态。
- **别让「模型只能重排」变成天花板**。早先的链路是「本地先命中 → 前 24 条交给模型挑」，
  中文需求一旦撞上本地的概念表没覆盖的词（比如「电动踏板车」），候选里根本没有对的东西，模型再聪明也挑不出来。
  现在改成三段：模型先把需求**拆成检索词**（`buildExpandMessages` / `parseExpandReply`）→ 用这些词对全库重新打分
  （`searchLibrary` 的 `extraTerms`，权重压到原句命中的 45%、封顶 1.1，只当辅证）→ 可选「全库扫描」
  把整库名字分段发给模型点名（`buildScanMessages` / `parseScanReply`，900 条一段、3 段并发）。
- **扫描分段的序号是「段内序号」，映射回去必须加 start，而且要和扫描用的那个数组对齐**：

  ```js
  const it = pool[payload.start + p.i];   // pool 是喂给扫描的数组（安静取向时它是筛选后的子集）
  ```

  这条我用 120 条、40 条一段的假 Agent 验过：三段回包各点第 7、33 条，最终落在第 7/47/87 与 33/73/113 条。
  如果拿 `state.items` 去映射 `pool` 的下标，安静取向筛过以后会整段错位。
- **图片一定要先缩小再发**。参考图动辄 3~8 MB，原样 base64 塞进请求会撞上体积上限、请求变慢、token 还翻几倍。
  `shrinkImageFile()` 用 `createImageBitmap` + canvas 缩到最长边 1024、导出 JPEG 0.82（1279×1598 的截图实测 118 KB）。
- **带推理的模型看图时 `max_tokens` 要给足**。DeepSeek 的 `deepseek-flash` 会先写一大段 reasoning，
  预算 2600 时偶尔 `content` 是空的（返回里 `finish_reason:"length"`）。所以看图失败会自动用 4600 重试一次，
  还是空就退回纯文字检索——别把「模型没说话」当成「模型说没有」。
- **模型挑的条目要对得上库**：`resolvePicks` 允许宽松 id，但如果它把名字截断了就会一条也对不上；
  这种情况要给出明确提示（「Agent 回了 N 条，但对不上库里的素材」），不要静默回落到本地结果。
- **「安静取向」的过滤只能按库统计、不能逐条拍脑袋**。一条 Wind 素材名字里可能撞上 `hit`，逐条用关键词判会误杀；
  按库（目录公共前缀之后的第一段，正好是音效包名）抽样统计「强冲突占比 ≥70% 且安静线索 <15%」才整库跳过，
  库名自己写着 BOOM / WEAPON / HIT 的把阈值降到 35%。跳过的条数和类别要显示出来，否则用户不知道结果为什么变少。
- **`candidateRows()` 只能读 `reasons` 数组**。扫描出来的候选只有 `reason`（单个字符串），
  漏了会导致 `r.reasons.join` 抛错、整条链在「终排」前静默中断（界面只停在扫描那一步的状态文案）。现在两处都兼容。
- **侧栏的计数不能用「每行扫一遍素材」的写法**。`countInCategoryTree(id)` 本身是 O(素材数)，`categoryChildren()` 里又在 `find` 父级（O(分类数)），两个叠在渲染循环里就是平方级：1553 个分类的清单渲染一次 2.6 秒、点一下卡 5 秒。现在 `categoryTreeIndex()` 一次遍历算好 `kidsOf` / 每棵子树的计数 / 未分类数，渲染循环只查表。以后再往侧栏加「每行一个统计」，先看它是不是 O(素材数)。

- **峰值计算的块内偏移 vs 全局帧号**（最隐蔽的一个）。`computePeaks` 按 1 MB 分块读文件，1 MB ÷ 6 字节/帧 ÷ 48000 Hz ≈ **3.64 秒**一块。如果拿全局帧号去索引**块内**缓冲区：

  ```js
  const base = frame * channels;   // 错：frame 是全局的，第二轮起就越界读到 0
  ```

  结果就是只有前 3.64 秒有波形，后面一条直线——而音频听起来完全正常。正确写法是两个下标分开：

  ```js
  const frame = frameBase + f;
  let bin = (frame / framesPerBin) | 0;   // bin 用全局帧号
  const base = f * channels;              // 取样本用块内偏移
  ```

  **改了峰值布局或生成逻辑，必须同时升 `PEAK_MAGIC`**（`src/main.js`，现在是 `SBP3`——`SBP2` 之后加过
  过零率/指纹的头部字段），否则用户机器上的旧缓存不会失效，改了等于没改。

- **从清单恢复的条目曾全部没有波形**。`makeItem` 里原本写 `analysis: file.meta ? 'ready' : 'idle'`——从 `library.json` 恢复的条目都带 `meta`，被当成「已分析」，于是永远不去主进程取峰值缓存。修法是给恢复的条目打 `needsAnalysis: true`。

- **`snd://` 的路径拼接**。`RENDERER_DIR` 本身已经是 `src/renderer`，如果再去拼 URL 里的 `renderer/index.html`，就变成 `src/renderer/renderer/index.html` → 404。现在统一用 `path.join(SRC_DIR, rel)`，再用 `WEB_ROOTS` 白名单挡住越界。

- **`window.prompt` 在 Electron 里不可用**（返回 null，什么都不弹）。新建/重命名资料库和分类用的是侧栏里的内联 `input`。

- **`File.path` 已在 Electron 32+ 移除**。要拿被拖入文件的真实路径，只能用 `webUtils.getPathForFile(file)`，已经包在 `preload.js` 的 `getPathForFile` 里。

- **拖出去给 DAW 的拖拽会被自己的导入逻辑接住**。`webContents.startDrag` 产生的拖拽会回到本窗口，`dataTransfer.types` 是 `['Files']`，跟「从资源管理器拖进来」完全无法区分——于是拖到一半全屏遮罩弹出来，松手还报「跳过 N 个重复」。现在的解法是把 `drag:start` 改成 `ipcMain.handle`（它阻塞到松手才 resolve，是唯一可靠的「拖拽结束」信号），配合渲染层的 `dragOutGuardUntil` 守卫，在拖拽期间一律不认导入。

- **空列表覆盖好清单**。渲染进程如果读 `library.json` 失败，会以空列表启动；一旦触发自动保存，用户的清单就被压平了。`saveLibrary` 写入前会先检查：新数据 `items` 为空而磁盘上的旧文件不空，就先备份成 `library.json.beforeempty`。

- **`.list-body` 的 `contain: strict`** 会把列表高度压成 0（`strict` 包含 `size`）。要用 `contain: layout style paint`。

- **波形「太平」不一定是 bug**。现场录音素材的峰值可能只有 -22 ~ -40 dBFS，画出来就是一条细线。为此加了**只影响绘制、不影响播放电平**的自动增益（`波形 适应` 按钮，倍率是 2 的幂，最多 64×）。要判断是素材本身安静还是算错了，直接扫 WAV 的 data chunk 算每秒峰值对照。

- **AIFF 在 Chromium 里不解码**，所以要转一份 WAV 到 `data\cache\wav\` 才能试听。原文件不动。

- **IPC 的结构化克隆是同步的**。`saveLibraryNow()` 原本把 10 万个条目对象直接丢给 `sb.invoke('library:save', payload)`，
  实测 102k 条光克隆就要 **388 ms**，表现为滚动时偶尔卡一下（条数越多越明显）。
  现在渲染进程自己 `JSON.stringify`，只把**字符串**发过去（主进程 `saveLibrary` 同时接受 `{json, itemCount}`），
  同一份清单的 IPC 时间降到 76~94 ms，最差帧 283 ms → 103 ms。要改保存逻辑，别退回「发对象」。

- **绝对不要用 PowerShell 的 `Get-Content` / `Set-Content -Encoding utf8` 去回写带中文的源码**。
  Windows PowerShell 5.1 的 `Get-Content` 默认按 GBK 读，UTF-8 的中文会被解成乱码再存回去（双重编码），
  而且会顺手吞掉末尾几行——这次真的把 `app.js` 写成过“闈欓煶”，最后只能从 `.bak1` 回滚。
  改文件用编辑器/`edit` 工具，或者用 Node/Python 明确以 UTF-8 读写。

- **`setData()` 会重置缩放**。打点（`I`/`O`）、切分类之类的操作会触发 `updateWavePanel()` → `wave.setData()`，
  而 `setData` 里把 `zoom` 归 1，于是「刚放大到 ×32 按一下 I 就跳回 ×1」。
  现在 `updateWavePanel()` 会先比 `srcKey = it.playPath || it.path`，同一份数据不重建 WaveView。

- **相似度不能用绝对差归一**。zcr（过零率）本身只有 0.02~0.07 量级，用「绝对差 ÷ 段数」算出来的差异
  会被噪声吃掉，结果同包络不同音高的两条能打 99 分。改成**相对差**（`|a-b| / max(a,b,ε)`）后，
  重复素材 100 分、同包络不同音高 92 分，才分得开。

- **逐样本裁剪要避开 float 往返**。`v / 32768 * 32767` 再四舍五入会掉 ±1 LSB（实测 `maxdiff 1`）。
  现在同宽整型（16/24/32-bit）走字节直搬 + 大小端翻转，实测与源文件**逐样本相同**（`maxdiff 0`）。

- **便携版重新打包会吃掉用户的清单**。`build_dist.ps1` 现在会先把 `dist\SoundBin\data\` 挪到临时目录，
  打完再放回去——不然每次重新打包等于把用户导入的东西删了。

- **`titleBarOverlay` 只在 Windows/Linux 生效**，macOS 上窗口按钮在左上角，所以 `style.css` 里有一条
  `body.platform-darwin .titlebar { padding-left: 82px }`，平台类名由 `app.js` 启动时读 `app:info` 加上。

- **封面目录是「音频所在目录」的子目录，不是父目录的**。第一版把 `Artwork` 的检查放在往上一层里，
  结果 BOOM 这种 `包名\xxx.wav` + `包名\Artwork\cover.jpg` 的结构找不到图（还误报 `ambiguous`）。
  现在每一层都是**先看该层的封面目录、再看该层的图**，然后才往上走，最多两级。

- **一整个音效包可以没有一张图**。用户装的 `14.BOOM Library Magic Bundle`（573 个 wav、11.4 GB）
  里只有 `info\*.pdf` 和 `_wfCache`/`peaks` 缓存，**没有任何 jpg/png**，PDF 里也只有 BOOM 的 logo。
  所以「给音频加图」做了两件事：真实图片按规定查找；**找不到就按目录名生成占位封面**
  （`placeholderArt()`，SVG data URL，稳定色相 + 两个字母）。别为了提高「命中率」去 PDF 里抽图——
  抽出来的只会是厂商 logo，不是封面。

- **BEXT 的日期/作者字段可能是二进制垃圾**。BOOM 的文件里 `originationDate` 全是 `00 00 00 80 …`，
  原样显示就是一串方块。`parseBext()` 现在只保留可打印字符，日期里没有数字就整行不显示。

- **`snd://` 协议注册时带了 `codeCache: true`，改了渲染层源码后 `Page.reload` 还是会跑旧字节码**。
  实测改完 `fx.js` 再 reload，控制台报的还是旧文件旧行号的同一个错，一度以为是没改对。
  **改完 `src/renderer/*` 必须整个进程重启**（打包版同理），别用刷新。

- **贴边隐藏不能靠「把窗口挪到屏幕外」**。多显示器上窗口会被系统捡到第二块屏上去，
  宽度也会被自作主张地改掉。现在的做法是**一直贴在屏幕边缘、收起时把宽度缩到最小**。
  另外 Windows 会把窗口宽度夹到 30 多 DIP（`setMinimumSize(8, …)` 之后实测是 24~34），
  所以「8 px 细条」是做不到的，界面上就按三十几像素呈现。

- **收起时原生标题栏按钮会被挤成一个 ✕**。窗口只剩三十几像素宽，`titleBarOverlay` 的三个按钮排在 138 px 的区域里，
  结果只剩最后一个关闭键露出来——手一抖就把应用关了。收起时要做两件事：
  `setTitleBarOverlay({ height: 1, symbolColor: 背景色 })`（只改 height 有时还画得出来），展开再还原。

- **两条补间动画会互相抢 `setBounds`**。展开和收起各跑一条 170 ms 的缓动，收起定时器在动画中途触发时
  两边会同时写窗口矩形，最后停在一个既不像展开也不像收起的宽度上（实测卡在 274 px，而 `hidden` 已经是另一个值）。
  `dockAnimateTo` 现在带一个代数计数器，旧的那条一发现代数变了立刻停手。

- **全局快捷键展开的面板会被自动收回去**。`Ctrl+Alt+S` 展开后鼠标还在别处，轮询到「鼠标不在窗口里」就收起了。
  键盘展开时要 `pinned = true`（自动收起逻辑认这个标记），再按一次才收起并取消 pin。

- **Windows 原生拖拽（`webContents.startDrag`）用合成的 `PointerEvent` 测不出来**。指针事件能触发渲染层的
  拖拽逻辑、`drag:start` 也会走到主进程，但 `startDrag` 要的是真鼠标，合成事件下它会安静地什么都不做。
  第一次拿合成事件测「拖到桌面」得出的结论是错的；改成**真鼠标拖拽**（automation 走 SendInput，坐标是物理像素，
  和 Electron 的 DIP 差 1.25 倍）后一次就成功。

- **`webContents.sendInputEvent` 生成的拖动没有图标会被丢掉**。补了 `drag-icon.png` 之后还是没反应，
  因为 `nativeImage.createFromPath` 在这台机器上取出来是 0×0（尺寸为 0 的图标会让 Windows 直接忽略整个拖动）。
  最后改成 `nativeImage.createFromBuffer(<内联 32×32 PNG>)`，和渲染层 `setDragImage` 用的是同一张图。

- **效果器开着不代表要拖出效果版**。`enabled:true` 但参数全是直通（20 Hz / 18 kHz / 0 dB / 干声 / 压缩关）时，
  离线渲染出来和原文件一模一样，白白多一次渲染、文件名还多一个 ` (fx)`。`fxAudible()` 先判断参数是否真的改变了声音，
  直通就还是给原文件。

- **贴边偏好只存在清单里，主进程不持久化**。那个「上次是不是贴着边、贴哪边、多宽」写在 `library.json` 的
  `settings.dock` 里，主进程每次都从头开始。启动时若拿 `dock:state`（主进程的内存状态）去覆盖渲染层恢复出来的偏好，
  重启后就永远贴不回去（实测 `enabled` 被冲成 `false`，宽度也回落到默认 480）。`dockRestore()` 现在以清单为准。

- **贴边小板子里的抽屉必须让出波形区**。抽屉原来是 `top:27px; bottom:0`，在几百像素宽、整屏高的窗口里会把
  波形条和效果器小开关整个盖住——那样检索出来的素材没法试听、没法修剪，等于白检索。
  `syncAiPanelBounds()` 量出波形区顶部，写成 `--ai-bottom`，抽屉和遮罩都改成 `bottom: var(--ai-bottom)`。

- **分类树要防悬空父级和环**。`parentId` 是自己写进清单的，手改过或者撤销出岔子时可能出现指向不存在的分类、
  或者 A→B→A 互相是父级；一旦成环，`renderCategories` 的递归会画不出侧栏。`repairCategoryTree()` 在加载时
  把悬空父级和环一律改回顶层，删分类时也会把子分类的 `parentId` 一起收拾掉。

- **导入时给每一条都算波形峰值，是「一万条素材导入卡死」的根因**。老流程每条要读完整段音频、
  主进程里算 min/max 包络（单个 20~60 MB 的素材 70~190 毫秒），还把所有峰值数组留在内存里
  （320 bins/秒 × 声道 × 双精度，一万条就是几个 GB）。现在拆成两段：`audio:probe` 只读文件头（2~4 毫秒），
  `audio:peaks` 按需才算、在 `src/peaks-worker.js` 里算、内存只留最近 8 条（`PEAKS_KEEP`）。
  同一个 `E:\声音`（9271 个文件）元数据出齐从「几分钟 + 吃满内存」变成 6 秒。

- **峰值计算必须离开主进程**。`computePeaks` 是同步的、几亿个采样；放在主进程里，一算起来所有 IPC
  （滚动要的 `audio:window`、保存清单、开抽屉）全都排队，界面直接假死。现在 4 个工作线程 + 队列，
  主进程只负责搬运 buffer（`postMessage` 带 transferList，不拷贝几十 MB）。

- **相似波形指纹改成了按需补**。指纹来自峰值，峰值按需算，所以刚导入的库里没有指纹。
  「相似」面板打开时每次挑 24 条待补的排队，算完一条刷新一次结果；关掉面板就停，补过的存进 `library.json`。

- **PowerShell 5.1 的 `Get-Content` 读 UTF-8 清单会显示乱码**，看到「缁忚繃澶勭悊」不代表文件坏了——
  那是按 ANSI 解出来的假象。核对中文内容用 `read` 工具或明确指定 `-Encoding UTF8`，绝对不要拿它去回写。

- **分类子树的展开必须是线性的**。`categorySubtreeIds()` 早期走 `categoryChildren()`（内部对 1553 条
  分类做 `filter`）再递归，展开「106 Fields & Spaces」（4428 条素材）时要几百万次比较，
  **点一下侧栏同步卡 8 秒**。现在统一用 `categoryTreeIndex()` 的 `kidsOf` 一趟走完，`computeView()`
  里只建一次索引再展开；18 次连点实测单次 ≤ 2 毫秒、没有长任务。

- **解除贴边时窗口会重建一次 DWM 表面**，偶尔整块客户区黑掉一帧。顺序必须是「先 `setBounds`
  （此时仍 `setResizable(false)`）→ 再放开最小尺寸和可缩放 → 恢复 titleBarOverlay」，最后
  抖 1 像素高度并调一次 `webContents.invalidate()`（`repaintWindow()`）把黑帧清掉。

- **贴边那排比想象的窄**。460 px 宽时四个按钮 + 时长 + 旋钮 + 右侧喇叭加起来就超了，
  旋钮会被挤出窗口外。贴边模式里把 `tbtn` 缩到 28 px、间距收到 6 px、时间码字号降到 12 px，
  旋钮才放得下；改底部布局后记得量一次 `getBoundingClientRect().right <= innerWidth`。
- **时间码不能画在波形区里**。以前刻度是画在波形画布最上沿的，响素材的峰值会把刻度盖掉。
  现在 `WaveView.rulerH`（15 px，面板矮于 90 px 时 13 px）在顶部留出标尺带，波形绘制整体
  下移并在 `rect(0, rh, W, H - rh)` 里裁剪，刻度画在带子里；改绘制代码时别把裁剪去掉。
- **拖宽不能每帧都 `setBounds`**。跟着鼠标每 7 ms 改一次窗口尺寸时，渲染进程来不及重排
  （这份清单有一千多个分类行），新露出来的那块区域会**黑着**——20:09 那段录屏里的黑屏
  就是这个。现在渲染层按 55 ms 节奏合并目标宽度（`setupDockResize` 里的 `RESIZE_INTERVAL`），
  主进程遇到宽度没变就跳过 `setBounds`，松手后再补一次 `repaintWindow()`。
  想让它更跟手可以把这个值降到 40 左右，但别再回到每帧一次。
- **`dragend` 靠不住，拖拽状态要自己收尾**。`webContents.startDrag()` 接管之后是系统在跑
  拖拽循环，HTML5 的 `dragend` 有时根本不发，那一行的 `.dragging`（`opacity:.45`）就会
  一直留着——「拖起又放下变灰、恢复不了」就是这个。现在 `startDragOut()` 的 `finally`
  里调 `clearDragMarks()`，另外还在 `window blur` / `pointerup` / `drop` 上挂了兜底，
  外加 15 秒看门狗（`drag:start` 永不返回时也不留灰）。
- **贴边的收起/展开动画也不能「每 8 ms 一次 `setBounds`」**。原来 170 ms 里连推 ~21 次，
  和上面那条同一个病因：表面重建太密，机器一忙就留下整块黑窗口（22:44 那段录屏里，
  面板从「消失」变成「整块黑」并一直黑着，就是展开这一步没画回来）。现在 `dockAnimateTo()`
  固定 240 ms、每步 34 ms（≈7 步），动画结束立刻 `dockSafeRepaint()`：先把高度按工作区
  高度抖 1 px 再还原、同时 `webContents.invalidate()`，并且**每次都拿工作区高度当基准**，
  不要在「当前高度」上加减（叠加几次会长高 4 px）。
- **黑屏要有兜底，但不能靠自动重载**。渲染层每 400 ms 发一次 `ui:alive`（`setInterval`，
  不用 `requestAnimationFrame`——窗口还没 show 时 rAF 不跑，大库启动会被误判成卡死）。
  主进程沉默 5 秒先强制重绘、8 秒 `hide()/show()` 踢一次 DWM 表面，都记在 `data\ui.log`。
  这里**刻意不自动 reload**：界面对「只是慢」的 reload 会变成重载死循环（实测 30 秒一轮），
  而渲染进程真崩了有 `render-process-gone` 单独兜底重载。


- **贴边的展开/收起不能「打断式反向」**。面板在边界上被反复要求展开/收起时，两段补间
  会互相打断，肉眼看到的就是面板在抽（22:41 那段录屏里左边缘来回摆 8–20 px）。现在
  `dockAnimateTo()` 发现上一次动画还没结束，就直接 `setBounds` 硬切到位，不再叠一段新补间；
  `dockPoll()` 的判定也加了缓冲：光标在窗口外 18 px 以内不算离开（6 px 内算在里面），
  只有真走远才起 620 ms 的收起定时器，收起后 350 ms 内不再展开。

- **原生拖拽期间不要动窗口**。`webContents.startDrag()` 是阻塞式模态，期间再 `setBounds`
  等于让 OLE 拖拽源和窗口几何抢消息队列——轻则抖，重则崩。现在 `drag:start` 会置
  `dockState.dragging`，`dockPoll()`/`dockCollapse()` 见到它就什么都不做，拖完 250 ms 再放开；
  同时拒绝并发拖拽（第二次调用直接返回 `{ok:false,busy:true}`）。

- **效果器版本拖出前，先按清单里的时长/大小挡一道**。原来只在 `decodeAudioData` 之后
  才判断大小，可解码本身就要几百 MB：长素材（≥8 分钟或 ≥120 MB）会直接把渲染进程吃崩，
  日志里只留一行 `render-process-gone crashed`，用户看到的就是「软件闪退」。现在
  `ensureFxDragFile()` 先看 `it.meta.duration` / `it.size`，超限就弹提示并回退原文件；
  解码后再按 `samples > 6e7` 或 `duration > 480` 复查一次。

- **闪退要留证据**。`ui.log` 现在除了心跳/黑屏，还记 `child-process-gone`、
  `uncaughtException`、`unhandledRejection`，以及每次拖拽的 `drag start n=… sizes=…` /
  `drag end`。下次再崩，直接对时间线看是拖到第几个文件、多大、崩在哪一侧。

- PowerShell 里写含 `$(` 的脚本必须用单引号 here-string（`@'...'@`）：用 `@"..."@` 时
  `$('btnImport')` 会被 PowerShell 当子表达式先执行，落到文件里变成 `\x08tnImport;`，
  现场报 `SyntaxError: Invalid or unexpected token`，而且 grep 中文会被 GBK 控制台弄成乱码，
  不容易一眼看出来。改 app.js 一律「python 脚本 + 单引号 here-string」，写完立刻 `node --check`。

- 收敛入口时不要只删按钮：`dom.chipInfo` 这类映射在初始化里是直接 `addEventListener`，
  元素被删掉就会 `Cannot read properties of null`。做法是保留映射、绑定处一律 `if (dom.x)` 守卫，
  新的总入口用 `showContextMenu(x, y, title, acts)` 现拼菜单，省得再写一套弹层。

## 给改这个项目的 AI 的说明

如果这个项目交给一个没有上下文的新会话继续改，先读这一节。

- **用中文思考和回复**，过程可以展示。用户看得懂英文但要求中文。
- **改完要真跑起来验证**，不要只读代码就说「改好了」。渲染进程可以通过 `--remote-debugging-port=9222` 用 CDP 连上去看 DOM 和 `console`，`window.__sb` 暴露了 `state`、`player`、`wave`、各种操作函数，够做端到端检查。交付前截一张图。
- **`window.__sb` 现在是完整的调试入口**：除了 `state/player/wave/addFiles/playItem/...`，还有
  `similarCandidates`、`setTrimPoint`/`commitTrimSelection`/`clearTrimSelection`、`exportTrimSelection`、
  `openInfoPanel`/`openSimilarPanel`、`scanAndAdd`、`deleteCategory` 等，
  以及这一版加的 `dockSet`/`dockRestore`/`applyDockMode`、`openAiPanel`/`runAiSearch`/`setAiOnly`/`aiRankMap`、
  `openFxPanel`/`fxApply`/`fxExport`/`syncFxUI`、`loadAgentConfig`/`saveAgentConfig`/`testAgent`/`scanPluginsNow`、
  `searchLibrary(q)`/`parseQuery(q)`、`ensureDragFile`/`collectDragFiles`/`startDragOut`、
  `createCategory(name, seed, parentId)`/`categorySubtreeIds`/`setCatCollapsed`/`syncAiPanelBounds`。
  改完功能先用它在 CDP 里跑一遍，比手点快得多。
- **贴边隐藏有原生窗口参与，CDP 里只能看到渲染层那一半**。判断它到底有没有贴边、收起到多宽，
  要问主进程：`await window.sb.invoke('dock:state')` 返回 `{enabled, edge, width, hidden, pinned, shrinkMode, shortcut, bounds}`。
  调宽度用 `dock:resize`（拖边时渲染层按 rAF 每帧发一次），拖标签栏解除贴边走 `window:detach`。
  鼠标坐标用 `screen.getCursorScreenPoint()`（DIP）；用外部工具模拟鼠标时给的是**物理像素**，
  这台机器缩放 125%，两者差 1.25 倍，拿物理坐标去判断「鼠标贴边没」会一直判错。
- **验证原生拖拽必须用真鼠标**。`webContents.startDrag` 对合成的 `PointerEvent` 无反应（见「踩过的坑」），
  合成事件只能验证到「渲染层决定拖哪个文件」这一层；文件到底有没有被拖出去，得看目标目录里出现了什么。
- **要压测就往独立的 profile 里跑**：`runtime\electron.exe . --user-data-dir=%TEMP%\data_stress --remote-debugging-port=9223`，
  这样不会碰用户真实清单。测完删掉整个 `data_stress` 目录即可。
- **不要动 `dist\SoundBin\data\library.json`**，那是用户真实的素材清单。要测导入/删除/合并，先 `Copy-Item` 一份备份，测完恢复，并且自己造的测试数据一定要清干净。
- **不要用「路径关键字匹配」来清理测试数据**。曾经用 `/PT\\(STONE|WOOD|METAL)\\/i` 去筛要删的条目，把用户自己导入过的同名目录素材一起删了。
- **不要用 PowerShell 往返读写源码**（见上面「踩过的坑」），中文字符串会被写坏。用 `edit` / Node / Python。
- **键位表在 `快捷键.md`**。改 `setupKeyboard()` / `setupWaveInteraction()` 之后要同步那份文档，不然用户按到的和文档写的会对不上。
- **不确定的数字不要编**。查不到就说查不到，能动手测就去测。
- 用户是声音设计师，判断标准是「听起来对不对」「拖进 Pro Tools 能不能用」，不是单元测试全绿。功能语义上拿不准的地方，宁可先问。

- **启动卡顿：`file:exists` 不能整库一次性 stat。** 旧实现是 `Promise.all(paths.map(stat))`，
  8 万条会同时甩出 8 万个 `fsp.stat`，全部挤进 libuv 的 4 个线程，把主进程读盘队列占满——
  界面能点，但试听/保存/峰值全都排在后面，表现就是「窗口出来了但半天不能用」。
  现在按 `path.parse(p).root` 分组：盘不存在（`fsp.access(root)` 失败）整卷直接判缺失不 stat，
  剩下的走 16 路并发 worker；渲染层也不再在首帧前 `await`，改成 `verifyMissingInBackground()`
  每 1200 条一块、块间 `setTimeout(0)` 让出主线程，完成后才 `computeSchedule + renderSidebar`。
- **贴边几何不要等到 init 末尾。** `dockRestore()` 只依赖存下来的偏好，必须紧跟设置恢复调用，
  否则用户先看到普通窗口、几秒后才「刷」地贴上边（大库时尤其明显）。
- **Stability 的 Stable Audio 接口只收 multipart/form-data。** 发 JSON 会 400
  `content-type: must be multipart/form-data`；要用 `FormData` 逐字段 append
  （`prompt / duration / steps / cfg_scale / output_format / seed`），`headers` 里不要手动设
  Content-Type（让 fetch 自己带边界）。另外它按秒计费：实测 12 秒 44.1k 立体声约 18.8 credits
  （≈1.57 credits/秒），不是「每次 8 credits」。
- **启动耗时用 `window.__startup` 打点。** `markStartup('settings' | 'dock' | 'items' | 'first-paint' | 'verify-done')`
  写在 init 的关键位置，远程调试里 `JSON.stringify(window.__startup)` 一次就能看到每段耗时，
  别靠肉眼猜「是不是音频太多」。
### 设置页加一个 tab，必须同时改 `SETTINGS_TABS`

`setSettingsTab()` 开头是 `SETTINGS_TABS.includes(tab) ? tab : 'general'`，只加按钮不往数组里加，
点上去会安静地跳回「常规」（1.8.0 加「音频生成」时踩过）。

### 暂存区存的是路径，不是条目对象

`state.bin` 里只有路径字符串，渲染时统一走 `state.byPath.get(path)`；
加载后必须 `filter((x) => typeof x === 'string')`，否则旧清单里混进 null 会让整块渲染炸掉。

### 一次生成多条 = 多次请求，各自计费

`genRunCloud()` 是按条数循环调 `gen:generate` 的，Stable Audio 按秒计费，
实测 8 秒一条约 9.4 credits；想省钱就先生成 1 条听效果。
